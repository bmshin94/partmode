# Sketch blocks and derived sketches

PartMode stores reusable two-dimensional sketch geometry as first-class schema-5 document records. Block definitions, block instances, and derived-sketch links use the `partmode.sketch-instances/v1` contract; modeling features consume their resolved closed profiles through the production constraint solver and exact OpenCascade path.

## Block definitions and instances

A block definition owns constraint-native point, line, circle, arc, or spline members plus its insertion point. Open layout and mechanism geometry is valid; a block is not required to be a solid profile. An instance refers to that shared definition and stores a translation, rotation, positive uniform scale, and optional fixed state. Positive transforms remain subject to the sketch solver and OpenCascade geometric tolerances; transformations that numerically collapse a rigid frame or solid fail closed. Editing a definition therefore changes every instance that refers to it; instances do not carry flattened copies of definition geometry.

The resolver transforms each definition into stable, collision-free `bi:`-qualified members. The qualification records the owner-ID length because authored IDs may themselves contain colons. It adds internal distance and radius relations plus a post-solve chirality witness, preserving one proper rigid participant without permitting reflected member configurations. A normal planar block instance consequently retains three external pose degrees of freedom: two translations and one rotation. Relations from ordinary sketch members to qualified block members participate in the same constraint solve. Fixing an instance fixes its member points explicitly; it is not inferred from a label or transform.

Placement relations have stable IDs and explicit create, update, and delete operations. Deleting an instance fails while a relation still references it. **Delete instance** removes an unreferenced instance and its geometry. **Explode block** instead resolves the current instance, materializes editable ordinary sketch members at the solved placement, preserves member IDs and coincident connectivity, rewrites relations that targeted its qualified members, and removes the instance link. The original shared definition remains available to other instances.

## Derived sketches

A derived sketch stores a source-sketch ID plus translation and rotation and inherits the source support plane and offset unless the create operation explicitly supplies another support. While linked, it stores no editable member geometry and rejects direct membership changes. Resolution follows the source, transforms its solved members into collision-free `ds:`-qualified members, and solves placement relations against the rigid derived result. Definition edits and source-sketch edits are therefore visible to downstream derived consumers on the next transaction and kernel evaluation. Relinking to a different source is refused because it would need an explicit member-identity map; linked derived-of-derived chains are likewise outside this bounded slice, so Underive the intermediate source first.

**Underive** resolves the current linked result, materializes it as ordinary editable sketch geometry, rewrites member relations, and removes the source link. Deleting a source sketch fails while derived or modeling-feature dependents still reference it. Derived cycles, missing sources, nested blocks, invalid member references, non-positive scale, and open modeling profiles fail closed.

## Exact modeling and bounded scope

Extrude and cut can refer to a first-class constrained sketch by `sketchId`. The project boundary requires one persistent sketch input reference, matching XY, YZ, or ZX base-plane support, no unrelated `onFace` reinterpretation, and the exact-sketch execution flag. Only those solid consumers require a complete closed profile; a blank or open reusable sketch remains valid document geometry. The production worker independently resolves the constraint graph and sends analytic lines, circles, and arcs—not display meshes—to OpenCascade. Qualified member IDs are retained as profile provenance for persistent topology naming. Spline members remain valid in general blocks and derived sketches but are refused as solid profiles until spline side-face history is complete.

This slice does not claim nested blocks, mirrored or non-uniformly scaled block instances, arbitrary surface-supported derived sketches, linked derived chains, first-class linked revolve, or solid-profile splines. A quarter-arc sector reaches exact OCCT construction, but a common semicircle-plus-diameter profile is deliberately refused when its seam produces ambiguous suffix topology naming; this is not general closed arc-profile completion. Pierce relations are refused until first-class sketches have a document-aware curve resolver. Reusable authored sketch, instance, and definition-member IDs are bounded to 60 characters, and one resolved sketch is bounded to 25,000 solver entities and 100,000 constraints before expansion. Before allocating the dense numeric Jacobian, the solver also enforces a 16,000,000-cell weighted work budget derived from free parameters and residual equations. Unsupported or excessive inputs are rejected instead of flattened or approximated.

## Typed operations

The transaction API exposes create, update, and delete operations for first-class constrained sketches and block definitions; create, pose-update, delete, and Explode operations for block instances; stable-ID create, replace, and delete operations for placement relations; and create, placement-update, and Underive operations for derived sketches. An inline constraint-native Extrude or Cut sketch can also be promoted into a first-class sketch. The project tree and dependency graph expose definition-to-instance-to-sketch and source-to-derived relationships.

The visible Sketch reuse manager exposes promotion, block capture from selected members, instance placement and lifecycle, relation JSON CRUD, and derived-sketch lifecycle. **New sketch**, **Edit sketch members**, and **Edit block members** open the ordinary constraint-native canvas rather than a metadata form. The same pointer tools, driving and reference dimensions, manual constraints, fix/unfix, merge, mirror, offset, and trim workflows edit a transactional draft; Apply sends the corresponding typed create or update operation, while Cancel leaves the canonical document, revision, history, and exact bodies unchanged. A selected linked derived sketch routes member editing to its source and retains the derived link.

Sketch-member editing resolves the full transient part graph, including block instances, placement relations, direct derived users, pending definition insertion-point changes, and every existing solid consumer. Linked geometry is drawn as read-only context. Authoritative solved coordinates, DOF, and conflict state therefore match the graph that the transaction will validate. Placement-related points are not locally dragged through an incomplete graph; their dimensions or relations must be edited instead. An edit that opens an Extrude or Cut profile, introduces a solid spline, breaks a dependent instance relation, or exceeds a solver boundary remains visibly invalid in the editor and cannot Apply. Pierce remains an explicit bounded exclusion and is disabled in reusable-member mode.

## Acceptance boundary

`smoke:sketch-blocks-derived` creates one shared constrained rectangle definition and two instances. It proves that a free instance has three pose degrees of freedom, then places a second instance with an external coincident relation and horizontal relation so that no pose degree of freedom remains. The test edits the shared definition and verifies that every instance updates, creates a linked derived sketch and verifies source-driven updates, and exercises Explode and Underive plus save/reopen and typed transaction behavior.

The production headless-worker gate extrudes the two constrained block profiles and the transformed derived profile on one warm OpenCascade worker. It requires valid exact bodies, analytic volume and bounds, complete persistent face/edge/vertex naming, qualified block or derived member IDs in topology provenance, current document hashes, changed canonical BREP bytes after source edits, and evaluated rather than stale reused features.

The browser-backed gate additionally authors a first-class rectangle and line profile with real canvas pointer input; edits source and block-definition dimensions; applies a pending insertion point in linked context; routes a selected derived sketch back to its source; and proves exact Cancel and invalid-edit rollback. Fresh isolated production workers recompute canonical B-reps for independent source, linked block, and derived Extrude consumers before and after those visible edits. The evidence requires matching current canonical document hashes, one valid solid, complete bounded topology counts, changed B-rep bytes, and changed analytic bounds and volume where appropriate. A schema declaration, tree row, screenshot, mesh count, or pre-flattened fixed copy does not satisfy this acceptance boundary.
